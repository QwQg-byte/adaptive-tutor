# 已知限制与后续建议

评估基线：阶段 7 总验收及学习状态统一验收，2026-08-03。建议在 2026-08-18 前后结合受控试用反馈复核。

## 决策摘要

| 项目 | 当前状态 | 建议决策 |
|---|---|---|
| S1 用户与服务端学习数据 | 学习数据已统一到服务端 SQLite；Demo 身份仍是客户端提供的 `student_id`，未接认证授权 | 受控试用可继续；公开使用前接入真实账户、权限、删除权和备份恢复 |
| S2 内容编辑与增量导入 | 部分具备；支持 `--no-clear` 和分数据源导入，缺少删除同步、审计和管理端 | 先做导入预览、差异报告、删除策略和回滚，再评估管理端 |
| S3 个性化路径算法 | BFS、拓扑和规则排序可用，未按掌握度训练或加权 | 先收集 8/18 前后的实际动线和完成率，再作为独立算法课题立项 |
| S4 OCR 与图谱联动 | OCR 原型独立存在，尚无版面检测、候选知识点和人工审核链路 | 继续作为独立课题，不并入当前发布范围 |
| S5 正式云端发布门槛 | 未完成域名、HTTPS、认证、异机备份和恢复演练 | 面向学生公开前必须全部完成，优先级最高 |

## S1 用户与学习数据

错题、掌握度、题目尝试和目标级计划进度现统一存放在 Tutor 的 `data/learner.db`，助手与图谱
通过 learner API 共享同一 `student_id + revision`。浏览器 `kg_learning_state_v1` 只作为一次性、
需确认的迁移输入和只读备份，不再接收新学习事实；清理浏览器不会删除服务端档案。

当前限制转移到了身份和部署边界：Demo 的 `student_id` 可由客户端指定，没有登录、授权和用户
找回机制；SQLite 适合单实例受控试用，不等于多机数据服务。公开或多设备使用前应一次性设计
身份来源、最小化个人信息、访问控制、导入导出、删除权、权限边界、数据保留周期，以及数据库
备份和恢复演练。不能把当前可编辑的 Demo ID 当成正式认证。

## S2 内容维护

`import_data.py` 已支持 `--no-clear`、`--kg-only` 和 `--questions-only`，因此“只能全量清库”
已不完全准确。但现有能力仍偏向运维导入：缺少变更预览、来源版本、删除/下线同步、冲突
处理、审计记录和内容审核界面。

下一步优先做无副作用的 dry-run 差异报告，并定义删除语义和备份回滚；这些稳定后再决定
是否需要管理端。不要直接把生产 Neo4j 当成内容编辑器。

## S3 路径与推荐

现有算法足以解释和复现，适合作为基线。短期继续使用规则方案并记录用户是否接受推荐、
是否完成计划、在哪一步退出。没有行为数据前引入复杂模型只会增加不可解释性，无法证明收益。

## S4 OCR 联动

当前 OCR 面向裁剪后的单行或短文本区域；整页课件仍需要文字检测和行切分。真正入图还需要
知识点候选生成、去重、来源追踪和人工审核。该链路应使用独立数据集和验收指标，不能直接把
OCR 输出写入正式图谱。

## S5 正式发布

当前云端仍是受控 HTTP，不能描述为正式生产环境。公开发布前至少完成：

1. 域名、HTTPS 和自动续期；
2. 与 S1 一致的认证和权限策略；
3. Neo4j 异机备份、保留周期和告警；
4. 在临时数据库或临时主机完成恢复演练并记录 RTO/RPO；
5. 复核云安全组、UFW、SSH 密钥策略和日志保留；
6. 外部题库授权与共同开发者署名书面确认。

## 其他工程限制

- `vis-network` 生产 chunk 约 635 kB，Vite 会给出大 chunk 警告；当前真实浏览器可操作，
  若后续首屏指标恶化，再评估延迟加载或拆包。
- 运行指标是单进程内存数据，多 worker 不共享；正式监控需要 Prometheus 抓取与集中日志。
- 图谱默认只加载约 200 个节点，不代表一次展示全部 1950 个实体；继续使用邻居展开接口。
- 外部题库实时抓取不在当前授权范围内，继续只使用仓库内或明确授权的数据。

决策顺序应为：先完成 S5，并把 S1 的认证、授权和数据治理接入发布链路；内容更新频率上升前完成 S2；S3 和 S4
保持独立立项，避免阻塞当前系统交付。
